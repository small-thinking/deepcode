# Minimum starting vertices: source reconstruction

The [Airbnb-tagged LeetCode discussion by Renzo Canepa](https://leetcode.com/discuss/post/124861/digraph-cover-all-vertices-with-the-least-number-of-vertices/) was opened and read on 2026-09-22. It specifies a directed graph that may contain cycles and disconnected subgraphs, and asks for the minimum number of starting vertices needed to reach every vertex. Its two examples return one and two after removing one directed edge. These are reproduced as executable checks.

The [saved Notion lead](https://app.notion.com/p/3cf6ce51456d81cc97faef54c003bec7) cites a [2021 phone-screen report](https://www.1point3acres.com/home/thread/716016) mentioning indegrees and disjoint cycles. The public question establishes the problem family; it does not prove that the 2021 report describes the same interview occurrence. No new interview occurrence or frequency increase is claimed.

The runnable interface `minimum_starting_vertices(n, edges)`, zero-based labels, empty-graph result, and acceptance of duplicate edges and self-loops are explicit practice conventions. The source supplies the general directed-reachability objective, not a Python signature, malformed-input policy, or requirement to return one particular starting set. The candidate returns only the minimum count. No invalid-input test expands this contract.

The reference uses iterative strongly connected component decomposition. One start is necessary in each component with no incoming edge from another component; choosing one vertex from each such component also suffices. Tests cover the source examples, disjoint and connected cycles, shared downstream nodes, isolated vertices, edge direction, self-loops, and duplicates. An independent exhaustive search over starting subsets checks all 512 directed graphs on three vertices. Two incorrect shortcuts are rejected: counting zero-indegree vertices and counting DFS roots in numeric order.
