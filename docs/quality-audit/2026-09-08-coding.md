## Test changes and independent evidence

- **385, existing wide-row case strengthened:** takes a row snapshot before traversal. Rejects an implementation that returns the right list after `row.reverse()` mutates odd rows. The prior mutation test had one column, so reversal could not change any row. Expected traversal follows the explicit row index rule.
- **386, new minimum-capacity multi-listing case:** capacities 8, 7, 6, 4 and target 12. No singleton fits; two-listing totals are 15, 14, 12, 13, 11, 10, so the unique best pair is 8+4. Rejects singleton-only and largest-capacities-first solutions, and checks non-mutation on success.
- **386, new tied-subset/neighborhood case:** eligible capacities 5, 5, 4 and target 9 yield tied pairs (first, third) and (second, third); original index chooses the first. Deliberately reversed lexical IDs reject ID-based tie-breaking. A foreign-neighborhood capacity 10 must not be selected. Target 15 is impossible because eligible capacity totals 14, detecting leakage from other neighborhoods.
- **387, existing five-task case strengthened:** checks full record/list equality after execution. Rejects in-place priority sorting that the old one-task non-mutation test could not detect.
- No invalid-input or stress cases were added. Existing 383 checks already cover strict descent, diagonal exclusion, negative heights, a singleton, empty starts, explicit validation, and ordered multi-start scores; extra examples would mostly repeat those behaviors. These small checks do **not** empirically enforce the memoization/time-complexity aim.
