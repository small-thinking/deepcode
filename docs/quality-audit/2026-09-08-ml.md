It does not preserve the notebook, TinyDenoiser architecture, function signatures, random draw order, or canvas/dtype policy. Those remain explicit practice choices. Visualization is acknowledged as an interview follow-up outside these executable APIs.
- The activation requirement remains an architectural requirement to review, rather than an assertion that a particular module class must appear. `nn.ReLU` and functional `torch.relu` implementations now pass. - Focal clipping previously said to clip before the logarithm while its reference reused clipped `p_t` in the focusing factor. The prompt now makes that existing practice convention explicit. No stricter endpoint test was added to force an implementation detail with negligible numerical impact.
- Crop's “numeric” wording is clarified as integer or floating point, the dtypes for which its pre-existing white-value rule is defined. No invalid-input exception policy is added.
