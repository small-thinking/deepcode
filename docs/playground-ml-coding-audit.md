# Playground ML coding contract audit

Audited on 2026-09-04 against the current local catalog and four saved Playground versions supplied from the live application. Saved sessions are practice artifacts, not independent interview-source occurrences: the new exercises carry no company attribution or frequency claims.

| Saved version | Existing related exercises | Full-contract difference and decision |
| --- | --- | --- |

Add **388** to practice the saved from-scratch PyTorch projection/autograd/general-mask contract. |
| `MHA.forward(x, mask=None, kv_cache=None)` returning current output and appended projected cache | 242 Causal Decoder, Masked Classifier, and Incremental Generation; 103 | 242 works with token IDs, classifier logits, and greedy generation, with caching optional. All four public signatures are preserved. Explicit educational refinements are constructor `ValueError` validation for invalid head counts/dimensions, numerically stable extreme sigmoid inputs, visible no-mutation checks, and numerical/autograd verification. Attention inputs are valid floating tensors; boolean masks are broadcastable and contain at least one allowed key per query. Fully masked rows are deliberately outside this contract. There is no implicit causal mask in the saved attention variants.

The three attention exercises use `evaluation.type=ml_coding`, `environment.runtime=pytorch`, deterministic small CPU tensors, and subprocess assertion checks that print `ok`. The NumPy exercise uses the Python runtime. This is forward/backward operator practice, so there is no downloaded dataset or training-quality harness. Per-head numerical references independently slice the projection matrices; cache tests compare token and multi-token chunk results with full causal attention and verify gradient connectivity and input-cache immutability.

Each new exercise declares one sandboxed `interactive_demo` asset at `assets/operation-theater.html`. The demos explain the exact exercise rather than replacing its executable tests. Reference implementations are stored as `solution.py` beside each exercise and are verified by `tests/test_playground_derived_fixtures.py`.
