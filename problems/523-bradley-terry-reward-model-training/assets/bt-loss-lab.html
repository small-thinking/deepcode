How one shared model produces these scores

Synthetic 1-D features: chosen x = +0.5; rejected x = −0.5. Reward r(x) = w·x + b, so the score gap Δ equals w.

Chosen reward c0.50(+0.5)·w + b
Rejected reward r−0.50(−0.5)·w + b
Δ = c − r = (+0.5 − (−0.5))·w + (b − b) ↓ two-way softmax over c and r p = exp(c) / (exp(c) + exp(r)) = sigmoid(Δ) Equivalently, Δ = log(p / (1 − p)): the gap is the model’s log-odds. ↓ negative natural log of that probability ℓ = −log(p) = −log(sigmoid(Δ))

Log-sigmoid means log of sigmoid, computed stably together. There is no softmax applied to a log.

The plots show one pair. Independent preference likelihoods multiply; taking logs turns their product into a sum. Negating and averaging gives the batch loss. These are predictions under the BT model, not guaranteed human preference rates.

Why compute log-sigmoid stably?

Taking log after a rounded-to-zero sigmoid can give infinity. The equivalent softplus form stays finite: max(0, −Δ) + log1p(exp(−|Δ|)).

What this toy can and cannot show

This is deterministic, full-batch SGD on a shared 1-D linear head, without regularization. Each update is one full-dataset epoch here. The explorer permits up to 400 updates to show long-run behavior; the exercise itself accepts at most 50 epochs. Higher-dimensional data can create other trade-offs, and noisy or incompatible features need not fit every preference. Training loss here says nothing about held-out generalization.

Changing the initial weight or scenario resets the trajectory. Changing the learning rate affects subsequent updates. Changing the shared bias only shifts displayed rewards.
